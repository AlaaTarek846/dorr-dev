> **الحالة الصريحة:** كل الباك إند عليه اختبارات آلية (`php artisan test --filter=Freelance` = 320 ناجح)، لكن **شاشات التطبيقين ما اتجرّبتش على موبايل** — الخطة دي هي أول تجربة بعين بشر. أي حاجة تطلع مختلفة عن "المتوقع" تتسجّل في عمود النتيجة.

### 0.5 ملفات الاختبار (مولّدة، مفيهاش بيانات حقيقية)

اعمل فولدر `C:\dorr-test-files` وحط فيه (كلها بتتولّد بأوامر، مش صور حقيقية):

```bash
mkdir -p /c/dorr-test-files && cd /c/dorr-test-files
php -r "foreach ([1,2] as \$n){\$im=imagecreatetruecolor(800,600);imagefill(\$im,0,0,imagecolorallocate(\$im,30*\$n,120,200));imagepng(\$im,\"design-\$n.png\");}"
printf '%%PDF-1.4\n%%%%EOF' > good.pdf
printf 'hello' > notes.txt
printf 'this is not an image' > fake-photo.png
printf 'MZ' > report.pdf.exe
printf '%%PDF-1.4\n1 0 obj<</S /JavaScript /JS (app.alert(1))>>endobj\n%%%%EOF' > active.pdf
```

ابعتهم للموبايل بـ `adb push C:\dorr-test-files /sdcard/Download/` (أو أي طريقة نقل). **الملفات السليمة:** `design-1.png` و`design-2.png` و`good.pdf` و`notes.txt`. **الملفات المرفوضة (للسيناريو ل):** `fake-photo.png` و`report.pdf.exe` و`active.pdf`.

## أوامر الوقت (لتجربة اللي بيحصل بمرور الأيام)

مجدولة وتشتغل لوحدها لو `php artisan schedule:work` شغال؛ وتقدر تشغّلها يدويًا:

| الأمر | بيعمل ايه |
|---|---|
| `php artisan freelance:release-due` | الاعتماد التلقائي للتسليمات اللي عدّت مدة المراجعة |
| `php artisan freelance:release-earnings` | تحويل الأرباح المعلّقة (`earnings.hold_days`) للقابل للسحب |
| `php artisan freelance:execute-disputes` | تنفيذ قرار النزاع الأول بعد أيام الاستئناف (لو ما حصلش استئناف) |
| `php artisan freelance:publish-reviews` | إظهار التقييمات لما تخلص مهلة الـ 14 يوم |
| `php artisan freelance:expire-agreements` | انتهاء الاتفاق اللي المحترف ما ردّش عليه |
| `php artisan freelance:interview-reminders` | تذكير المقابلات (كل دقيقة) |
| `php artisan freelance:reconcile` | مطابقة الفلوس (يومي 03:20) |

> غالبًا هتحتاج تعدّل التواريخ في الداتابيز (أو تضبط `earnings.hold_days`/`review.days` على قيم صغيرة من Policies) عشان تشوف الأثر من غير ما تستنى أيام.

## قايمة فحص سريعة للـ UX والتجربة (على كل شاشة)

- ☐ الاتجاه من اليمين لليسار سليم في العربي ومفيش نص مقطوع.
- ☐ كل خطأ من السيرفر بيظهر رسالة مفهومة (مش `HTTP 422`).
- ☐ شاشات القوائم فيها حالة فاضية وحالة تحميل وزرار "Show more" عند الصفحات.
- ☐ لا شيء بيتحدّث بتايمر — الجديد بيوصل لحظيًا (الشات، حالة المرحلة، الإشعارات) ولو النت فصل ورجع يعمل تحديث واحد.
- ☐ الإشعارات بتوصل (لحظي + OneSignal لو متفعّل) وفتح الإشعار بيودّي للشاشة الصح.
- ☐ الوضع الغامق/الفاتح سليم على كل الشاشات الجديدة (التسليم، قايمة القبول، المقابلة، الدعوات).
- ☐ كل زرار يتأكد قبل أي فعل مالي (التمويل، الاعتماد، الإلغاء، الدفع، السحب).
- ☐ مفيش بيانات تواصل بتتسرّب قبل الاتفاق.

## تسجيل المشاكل

لكل مشكلة اكتب: رقم الخطوة · الحساب · اللي حصل · اللي كان متوقع · لقطة شاشة (لو الشاشة نفسها المشكلة). المشاكل اللي فيها فلوس (رقم غلط، فلوس اتخصمت مرتين، أو ما رجعتش) تتعلّم **حرجة** وتوقف باقي السيناريو.
