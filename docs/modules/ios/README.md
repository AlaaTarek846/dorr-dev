# iOS App (`iosApp/`)

**Last updated:** 2026-10-28

The native iPhone/iPad twin of [androidApp](../android/README.md). It talks to the same backend (`/api/mobile/v1/*`, guard `user_api`, Sanctum Bearer token) and must stay in step with Android. See the **Android → iOS sync rule** below.

## Stack

| Item | Value |
|------|-------|
| Language / UI | Swift 5, SwiftUI, iOS 16+ (iPhone + iPad) |
| Project | Generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `iosApp/project.yml`. `Dorr.xcodeproj` is not committed. |
| Bundle id | `com.dorr.app` (same placeholder as Android) |
| Network | `URLSession` + `Codable` (no third-party packages yet) |
| Session | Token in the Keychain, user JSON in `UserDefaults` |
| Strings | Generated from the Android XML (`scripts/sync_strings.py`) |

## Build and run

Accounts and keys a release needs (Apple Developer, App Groups, APNs, OneSignal, Firebase, Google Maps): [SETUP-CHECKLIST.md](SETUP-CHECKLIST.md).

```bash
brew install xcodegen            # once
cd iosApp
cp Config/Local.xcconfig.example Config/Local.xcconfig   # pick your backend
xcodegen                         # after adding/removing files or editing project.yml
open Dorr.xcodeproj              # or build from the command line:
xcodebuild -project Dorr.xcodeproj -scheme Dorr -destination 'generic/platform=iOS Simulator' -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```

The backend is set in `Config/Local.xcconfig` (`DORR_API_HOST`, `DORR_API_SCHEME`). It is ignored by git, like Android's `local.properties`. Its value reaches the app through `Info.plist` (`DorrApiHost` / `DorrApiScheme`). Media URLs built with `dorr.test` are rewritten to that host (`ApiClient.mediaUrl`).

## Android → iOS sync rule

Android is the reference app. **Every change to `androidApp/` must be made in `iosApp/` in the same task.**

1. **Strings:** automatic. Edit the Android XML only. `scripts/sync_strings.py` regenerates the iOS files. It runs on every Xcode build, and the Claude Code hook runs it after every edit of a `strings.xml`.
2. **Code:** port the same behavior to the twin file in the table above. Use the same names (screens, APIs, DTO fields, store keys) so the twin is easy to find. The Claude Code hook (`.claude/hooks/android-ios-sync.sh`) reminds the agent after every Android edit.
3. **Not ported yet?** If the Android area has no iOS twin yet, add or update its row in the parity table below. Don't silently skip it.
4. **Platform-only things:** some pieces have no iOS meaning (Google Play review, `SYSTEM_ALERT_WINDOW`, foreground services, R8). Note "Android only" in the table and move on.
5. **Check:** `scripts/ios-parity.sh` lists the Android files changed since the last commit that touched `iosApp/`.

## Wallet (`UI/Wallet/`)

A line-by-line port of `androidApp/.../ui/screens/wallet/` (25 Kotlin files) and `network/WalletApi.kt`. Same endpoints, headers (`X-Wallet-Pin`, `Idempotency-Key`, `X-Country`), strings, colours, sizes, steps and error handling. Opened from the Home header's wallet button and the Account tab's wallet card. It sits over the tabs with the tab bar still visible, and no tab is highlighted while it is open. Leaving it locks it again.

Where iOS differs (same behaviour, platform tools):

| Android | iOS |
|---------|-----|
| PIN in the Android Keystore behind `setInvalidatedByBiometricEnrollment(true)` | PIN in the Keychain behind `.biometryCurrentSet` (a new face or finger deletes it; `WaBiometric`) |
| ZXing encode / capture screen | CoreImage `CIQRCodeGenerator` (level M, 2-module margin) / AVFoundation camera, `CIDetector` for a photo |
| Gallery `GetContent`, camera `TakePicturePreview` | `PhotosPicker`, `UIImagePickerController` (front camera for the selfie) |
| `MediaStore.insertImage` | `PHPhotoLibrary` (add-only permission) |
| WebView for the sandbox bank, browser for real gateways | `WKWebView` / Safari, same rule |
| Material icons | SF Symbols (`ic_ms_add_card` → `creditcard.and.123`, `ic_ms_credit_card_clock` → `clock.arrow.circlepath`) |

Permission texts (Face ID, camera, adding to Photos) are in `Info.plist` and `Resources/{en,ar}.lproj/InfoPlist.strings`. These are written by hand; they are not part of the strings sync.

The top-up and checkout waiting pages ask the server every 2 s while a gateway payment is pending (at most 100 / 150 times), exactly like Android. This goes against the "no polling" rule in AGENTS.md. If it changes, change both apps together, for example to a `wallet.*` realtime event.

### Looking at the screens without a server (DEBUG only)

```bash
xcrun simctl launch booted com.dorr.app -DorrFixtures YES -DorrWalletRoute home   # or gate|topup|transfer|confirm|qr|scanner|history|pin|checkout
```

`-DorrFixtures YES` answers every request from `Debug/DebugFixtures.swift` (real decoding, real screens). `-DorrWalletRoute` signs in with a placeholder token and opens the wallet on that page, skipping the PIN gate except for `gate`. Add `-dorr_locale en` for English. None of this is compiled into a Release build.
