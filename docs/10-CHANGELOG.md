### Changed
- **Calendar / Moments hero (app):** `DarkHeroPanel` was locked to light tokens (`night = false`), so Dark in Appearance left the navy header as-is while Home followed the dark primary. Night now uses the same dark `primary` as the Home greeting bar.
- **Moments page (app):** the top bar is the same navy + brand-red rounded panel as the calendar (`DarkHeroPanel`), with the same settings cog. The occasion card sits on the page below that panel, not inside it. Quick actions sit in one hairline card; the coming-up list is the same bordered card. Dates follow the app locale. Adding a date: month and remind-me are selects; the sheet opens fully so Save stays on screen (`skipPartiallyExpanded`). New group card (`CreateCollabSheet`) is the same: it skips the half-open peek so Start stays on screen, occasion and recipient are pill selects, title and invite are labeled `DorrTextField`s. The card preview is tall enough for the occasion name (it was clipped at 120 dp). Capsules list uses the same rows and type as the coming-up list. New capsule is a light sheet with the same pill fields (not the chat navy `ChField`). Send-card composer matches the same fields; surprise / later / gift use the Account notification `RedToggle` (pink icon, 13.5 / 11 type) not Material `Switch`. Schedule-message (`ScheduleSheet`) is the same Account card of rows (pink icon, 13.5 title, 11 time) and opens fully so "Pick a day and time" stays on screen.
- **Calendar appointment form (app):** date, start and end are the same pill inputs as title and location (label above, icon inside). Tapping opens the picker; they are not chevron rows. An empty end shows the "No end" placeholder, with a clear × when a time is set. Remind me is a select (same pill, down arrow, menu under the field). The appointment detail sheet is denser: icon wells, hairline rows, and it opens fully so the edit button stays on screen.
- **Occasion settings (app):** the screen matches Account notifications: one card for Show occasions, Animations, and Country occasions. Animations and Country occasions are rows with the current value in parentheses (`الأنيميشن (كامل)`) and open their own screens. Country occasions is a dropdown (search, login country first) with the "which occasions" list under it; changing country reloads `GET moments/catalog?country_id=`. A long country name ellipsizes so the chevron stays aligned.
- **Calendar item sheet (app):** the detail sheet (title, kind, when, open/edit actions) is denser: a kind chip, a bordered details card, and a 44 dp button instead of the large wallet CTA.
- **Calendar list cards (app):** appointment/occasion rows are denser (Account-sized icon tile, smaller type), the same height for timed and all-day items, and a light 1 dp border instead of a heavy shadow.
- **App language on sheets, dialogs and dates (Android).** Dialogs and bottom sheets are their own windows, so they used to read English (`values/`) and name days/months in the phone's language. `ChSheet`, remaining `ModalBottomSheet`s (notifications, home services), `LocaleAwareDialog` / `AlertDialog`s, and date formatters now follow the in-app language (`AppLocale.java()`).
- **Calendar (app):** the top of Today / Week / Month is a navy + brand-red panel with a rounded bottom edge (title, search, settings, back, and the day/week/month pills). On Week the week strip sits in the same panel. Lists and the month grid stay on the light page below.
- Calendar filter chips now follow Settings: a kind whose source is off has no chip, the chips follow the Today order, and on the Today tab a kind hidden in "Today page" has none either. A chosen chip that goes away falls back to "All".
- Calendar appointment form: the "Type" choice is gone (every appointment is a plain appointment); its icon, label and the Settings "kinds" page went with it. The `category` column stays in the database, unused by the app (defaults to `appointment`).
- Admin Discover events (`/admin/discover/events`): UI matches the countries catalog (breadcrumb header with total badge, catalog toolbar with search + clear, PrimeVue Select filters, striped table with empty state, pagination-style-4 footer). The add/edit and status modals use PrimeVue Select and AdminDatePicker (with time) instead of native select / datetime-local.
- Admin Chat occasions (`/admin/chat/moments`): the list matches the flags catalog (breadcrumb, search, active/inactive filters, MultiSelect type with search, status toggle, pagination, row checkboxes and bulk delete). Toggling status shows "Updated successfully." The countries column shows translated names (or "Everywhere" when none / all are selected). Created at matches flags (date + updated subtext, after status). Next uses the same locale date format, with the date rule as muted subtext. The dates & corrections modal shows country names and AdminDatePicker fields in compact rows. Create/edit fields match catalog modals (input-group + icon, PrimeVue Select/MultiSelect, status/default toggles, card image picker).

- Admin sidebar Chat screens (reports, themes, settings, …) show only when the header service is Chat (`service_categories.module_name = chat`), same as AI with `ai_assistant`. They no longer stay under General, and the placeholder inbox/groups/channels/archive menu is gone.

- Android Home today card when the day is empty: the small label is "Your day is free" / "يومك فاضي", and the main line is today's date (`Thursday, 8 October` in English).

- **Account security (spec 27–29).**
  - **Sign-in behaviour changed:** signing in no longer signs the account's other devices out. Each sign-in (app OTP, web password, password reset) gets its own Sanctum token and an `account_sessions` row with the device it came from. The app now sends `X-Device-Name`, `X-Platform` and `X-App-Version` next to `X-Device-Id`.
  - The same device signing in again replaces its old session. Past `auth_flow.max_sessions` (5) the device used longest ago is signed out. A password reset signs every device out.
  - Signing a device out deletes its token, so its next request gets a 401, and drops its push ids (`notification_devices.device_id`).
  - Tokens from before this change show up as devices too.
  - **Devices** (`GET/DELETE /api/mobile/v1/security/devices`, `POST .../logout-others`): the device list shows the IP partly hidden, and the country only for a public IP.
  - **Security log** (`security_events`, `GET /api/mobile/v1/security/events`, paginated, `warnings=1`). It records:
    - sign-ins and sign-ins from a new device;
    - wrong passwords, codes asked for, wrong codes and code lockouts;
    - log-outs, devices signed out (by the owner, by the limit, by support);
    - phone changes, wrong wallet PINs, PIN lock and freeze, and account restores.
    - Rows are kept `auth_flow.security_log_days` (365), pruned daily by `model:prune` in `routes/console.php`.
  - **Intrusion alerts** (`SecurityAlerts`), sent in-app, live and by push in the owner's language, at most once per 15-minute window each:
    - 3 or more wrong codes or passwords;
    - 5 or more sign-in codes asked for;
    - a sign-in from a device the account never used.

- **Call recording (spec 92, safety rule 1):** a call is recorded only once everyone in it said yes. Someone asks (`POST chat/calls/{call}/recording`) and everyone else answers within 30 s (`.../recording/consent`). One "no" or silence, and LiveKit is never asked. Someone joining a call that records gets `409 chat_recording_consent_required` and joins only with `recording_consent`. Anyone stops it (`.../recording/stop`), and it stops with the call. LiveKit Egress records the room (camera grid for video, voices for voice) as one MP4 straight into a private S3-compatible bucket (`CHAT_RECORDINGS_*`; LiveKit Cloud has no storage of its own). Only the people who agreed play it, through a 15-minute signed link (`GET .../recordings`; AWS Signature V4 signed in `Support\RecordingStorage`, no SDK). Files are deleted after the admin's `call_recording_retention_days` (30). `chat:call-recordings` runs every minute. Event `chat.call.recording`; the call's line in the chat gets `meta.recorded`.
